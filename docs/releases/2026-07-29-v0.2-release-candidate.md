# SYCO23 SETCRAWLER v0.2 Release Candidate

Date: 2026-07-29  
Status: release candidate; production promotion pending external gates

## Release outcome

The durable import pipeline now recovers from early retry delivery, expired
worker leases, and complete Redis message loss without processing a retry
before its scheduled time or resetting its failure budget.

Key changes:

- `claim_job` enforces `next_retry_at` in memory and PostgreSQL.
- `details.retry_count` is the durable retry-budget authority across recreated
  Celery messages.
- `list_recoverable_jobs` exposes only queued, due-retry, or stale-processing
  rows.
- Celery beat republishes a bounded recovery batch every 60 seconds.
- Local Redis uses AOF with a named persistent volume.
- Database claim fencing keeps duplicate redrive publications idempotent.

## Production gates

- GitHub Actions must pass on the release branch.
- Select the production Supabase project, apply all migrations in order, and
  run security/performance advisors.
- Confirm explicit Data API grants because new Supabase projects no longer
  expose newly created public tables automatically.
- Create or link the Vercel project with root directory `apps/web` and set its
  public runtime variables.
- Provision a persistent API/worker host with PostgreSQL connectivity, Redis
  persistence, four Celery workers, and Celery beat.
- Run credentialed smoke tests for YouTube, manual SoundCloud metadata import,
  and the opt-in FTM scraper.
- Configure the private storage buckets before enabling the image pipeline.

## Rollback

The change adds no database columns or tables. Rollback consists of deploying
the previous API/worker image and stopping Celery beat. Preserve PostgreSQL
`import_jobs`; they remain compatible with the previous schema. Do not delete
the Redis volume during rollback.
